Accessibility

Misket is built to be used entirely with the keyboard and to make sense read aloud. This page says plainly what is supported today, what is not yet, and where to report something that does not work for you.

Screen readers

  • Every icon-only button has an aria-label — the lucide icons themselves are marked aria-hidden by the icon library, so they never announce twice.
  • Dialogs carry a real title and description (Radix UI's own console warning for a missing one is clean throughout); closing one returns focus to what opened it.
  • The code tree is a proper role="tree", with treeitem, aria-expanded, aria-level and aria-selected, and arrow-key navigation.
  • The sidebar's Documents/Codes switcher and the analysis view's list of analyses use tablist/tab/tabpanel and nav/aria-current respectively; the document list and the excerpt browser's rows are focusable, named list items.
  • Toasts are role="status" (an error toast is role="alert", so it interrupts rather than queues).
  • Inside the document text, the contract that makes overlapping highlights possible — every character lives in a span[data-s] with a single text node and nothing else — means a coded range cannot carry a visible label of its own. It is named for assistive technology instead: a title and aria-description on the span naming its codes (for example Coded: Autonomy, Trust), the text container itself is role="document" with the open document's name, and the currently focused excerpt carries aria-current.

Keyboard

Everything in Misket is reachable without a mouse — the full reference is on the Shortcuts page. A few things specific to accessibility:

  • Skip to document is the first focusable element in the workspace, before the sidebar.
  • Every focusable element has a visible focus ring in both light and dark themes (:focus-visible, not removed by a CSS reset). There is no positive tabindex anywhere.
  • Dialogs trap focus while open (Radix UI) and hand it back on close; the code palette (Ctrl/⌘+K) returns focus to the document.
  • Tab/Shift+Tab move between excerpts while the open document, image or media pane's own neutral surface has focus — where it lands right after you open or navigate to one. The moment focus is on an actual control instead — a sidebar button, a dialog, a menu — Tab goes back to moving focus normally, so nothing outside the document is ever unreachable by keyboard.

Contrast, in both themes

Every text-on-background and focus-ring-on-background colour pair in Misket's design tokens clears WCAG AA: 4.5:1 for text, 3:1 for a focus ring and for the boundary of an input, a select or the outline button style. This is checked in code (src/core/contrast.test.ts) against the actual tokens in both the light and dark theme, not eyeballed once and left to drift — including the tint a highlight mixes under coded text, checked against the lightest and darkest colours in the default code-colour palette.

Motion respects prefers-reduced-motion: the toast "said again" shake and the flash when you jump to a coded excerpt both drop their animation and fall back to what they were signalling (a repeat count, a highlighted outline) without it.

What is not there yet

  • There is no way yet to place the very first text selection with the keyboard alone in a document with no excerpts: extending a selection by word (Alt+Shift+←/→) needs either a live selection or a focused excerpt to grow from. A screen reader's own virtual cursor already places a real selection Misket reads correctly; a sighted keyboard-only user currently cannot start one without a first click.
  • Audio and video have no caption track — Misket does not transcribe a recording's audio automatically.

Report a problem

If something does not work for you with a screen reader, with the keyboard alone, or at a contrast setting your operating system asks for, please open an issue. Say which screen reader and browser engine you were using if relevant (Misket's window is WebKit on Linux, WebView2 on Windows, WKWebView on macOS) — accessibility reports are treated as bugs, not feature requests.
