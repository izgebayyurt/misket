Translating Misket

Misket's interface ships in English and Türkçe today. Settings → Language switches between them (or follows your OS/browser locale) with no restart. This page is for anyone who wants to improve the Turkish translation or add another language.

How it fits together

The app uses i18next and react-i18next. Every user-visible string in src/components/** is a call like t("settings.you.title") rather than literal English text; the key is a stable, dotted identifier grouped by area (codebook.rename, history.goToPoint), never the English sentence itself. Two JSON files hold the actual text, one per language, with the same shape:

  • src/locales/en/common.json — the source of truth for which keys exist.
  • src/locales/tr/common.json — the Turkish text for every one of them.

A count-dependent string has two forms per language, suffixed _one and _other ("stepCount_one": "{{count}} change", "stepCount_other": "{{count}} changes") — i18next picks the right one from the count you pass it. Turkish only ever needs one wording (Turkish nouns don't change after a numeral), so its _one and _other entries are identical text; they are both still present, so a future language with real plural forms is unsurprising rather than a special case. Dates, relative times and numbers are not baked into the JSON at all — they go through Intl.DateTimeFormat, Intl.RelativeTimeFormat, Intl.NumberFormat and Intl.ListFormat in the active locale at the point they're displayed, so a thousands separator or a weekday name is always correct for the language on screen.

Adding or improving a translation

  1. Edit the matching key in src/locales/<lang>/common.json (src/locales/tr/common.json for Turkish). Keep placeholders like {{name}} or {{count, number}} exactly as they are — only the surrounding words move.
  2. To add a new language: copy src/locales/en/common.json to src/locales/<code>/common.json and translate every value (not the keys); register it in src/lib/i18n.ts's resources and src/core/locale.ts's SUPPORTED_LOCALES; add it to LANGUAGE_OPTIONS in src/components/layout/SettingsDialog.tsx and the Rust Language enum in src-tauri/src/settings.rs.
  3. Run pnpm i18n:check (also part of pnpm check): it scans every t(...) call under src/** and fails if a key a component uses is missing from either locale file, or if a key in a locale file is not used anywhere — so a typo'd key or a stray leftover string is caught immediately, not after release.
  4. pnpm test mounts a real component under Turkish and checks a Turkish string renders, and checks the plural-form and Intl-formatting rules for both locales — worth running alongside the check script.

What is deliberately not translated

  • The activity log and undo history. A step's stored summary ("Merged code X into Y") and the raw fields in the history detail panel are an audit trail, written once in whichever language was active at the time — translating them after the fact would mean the record no longer says what actually happened. See docs/DATA_MODEL.md.
  • Export headers. CSV and JSON column names stay in English so exports open predictably in other tools and scripts that expect them.
  • Backend error messages. A Rust-side AppError.message stays English (it is meant for logs and bug reports as much as for the screen), but carries a code the frontend can map to a translated headline where one exists.

Terminology

The Turkish translation uses established Turkish qualitative-research vocabulary: kod (code), kod defteri (codebook), alıntı (excerpt/quote), not/memo (memo), betimleyici (descriptor), kodlayıcı (coder), güvenilirlik (reliability), birlikte oluşum (co-occurrence), ağırlık (weight), tarihçe (history), dal (branch), çatal (fork). Product names (Misket, REFI-QDA, OCR) are never translated.
