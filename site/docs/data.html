Data & privacy

Misket is local-first: there is no server, no account and no telemetry. Your project lives in one file, on your own disk, and nothing about it is ever sent anywhere.

The project file

A project is a single .misket file — a SQLite database — wherever you save it. Every document, code, excerpt, memo and descriptor lives in that one file. Document text is normalized once at import (line endings, Unicode form) and is then immutable, so excerpt positions stay valid for the life of the project.

Backups

Before a destructive change — deleting a document, deleting a code that has excerpts, merging one code into another, or importing a codebook — Misket automatically writes a timestamped copy into a <project name>.backups/ folder next to the project file, and keeps the newest 20 (configurable in Settings). Use Backups… in the status bar to see each backup's size and reason, and to restore one; restoring backs up the current state first, so it is never itself destructive. Use Export → Save a copy as… at any time to make a manual snapshot. None of this replaces your own backup discipline for anything that matters — keep the project file (and its backups folder) somewhere that is itself backed up, such as a synced drive or version control.

The activity log

Every change you make — creating, renaming, moving or merging a code, coding or adjusting an excerpt, writing a memo, setting a descriptor — is recorded inside the project file, with the name of whoever made it and when. Because it is part of the file, the trail is copied, backed up and restored with the data it describes, and it travels with the project when you hand it to a colleague or a reviewer. The overview screen lists the latest entries, a code's or an excerpt's inspector shows its own history as a timeline (including the values before and after each change), and Export → Activity log (CSV) writes the whole thing out. The name is yours to set in Settings; with none set, Misket uses your computer's user name. There are no accounts and nothing is verified — this is a record for your own transparency, not an authentication system.

Who coded what

Every code you apply and every memo you write is signed with a coder: a name, a colour and an id this copy of Misket generates once and keeps in its settings (Settings → “You”). The id is private and meaningless on its own — it exists only so that two copies of the same project can be told apart when they are brought back together.

Because a coding belongs to a coder, two people can apply the same code to the same passage without overwriting each other: those are two codings of one passage, and the excerpt inspector shows a small mark for each. Removing a code takes back your coding and leaves your colleague’s; the menu offers to remove theirs explicitly when that is what you mean. The excerpt browser and the analysis views have a “Coders” filter (everyone, only me, or any of them), the document view can colour its underlines by coder instead of by code, and the overview screen lists everyone with how much they have coded.

Every count in Misket — frequencies, co-occurrence, code × document, the cross-tabs — counts passages, not codings, so two people agreeing never makes a code look twice as common. Narrow to one coder to ask how much that person coded.

Working with a team

There is no server and no shared database, so two researchers working on one study keep one file each, side by side in a shared folder, named for who writes in them: study.ada.misket, study.bob.misket. Each of you opens only your own file — never the other person’s — which is also what keeps a synced folder safe, because two machines never have the same file open.

Whenever you want the other person’s work, use Pull from a copy… in the status bar and pick their file. Misket reads it, shows you what it would bring across — how many documents, codes, excerpts and codings, and who made them — and pulls only when you say so. Nothing is ever written to their file, and nothing of yours is ever removed: a pull only adds. Pull again next week and only what is new comes over.

Most of a merge needs no decisions. The same passage coded by both of you is one passage with two codings, not a duplicate; a code you both invented under the same name is one code carrying both people’s work; a document imported separately from the same file is recognised by its contents, and their excerpts land on your copy of it. What Misket cannot decide for you is something you have both edited — a code you have each renamed, a memo you have each rewritten, a framework summary you have each filled in — so it asks, side by side, with the answer that loses nothing preselected. The first time you pull from someone there is no shared starting point to judge those edits against, so your version always wins and the differences are listed as notes.

The whole pull is a single step in the history: if you do not like the result, Undo takes all of it back at once, and Redo puts it back. Once you both have each other’s work, Reliability — under Team in the Analysis list — compares how the two of you coded the same material.

Cloud-synced folders

If you create or open a project inside a folder a cloud sync client manages — Dropbox, OneDrive, Google Drive, iCloud Drive, Box, Nextcloud, ownCloud, Syncthing, MEGA, pCloud and similar — Misket shows a dismissable warning. Sync clients rewrite files out from under applications, and doing so while a database is open is a documented corruption path in other QDA tools (NVivo and MAXQDA's own support articles both name it). The warning's Move project… button writes a copy to a folder you choose, opens the copy, and removes the original from Recent — without deleting the original file, just in case. Keeping the project where it is works too, as long as you close Misket before the folder syncs to another machine.

Export formats

  • Codebook — CSV, or a JSON file that another Misket project can import to reuse the same codes.
  • Excerpts — CSV, one row per excerpt with its codes, the coders who applied them, document, position, text and descriptor values.
  • Activity log — CSV, one row per recorded change with its time, actor, kind, target and a readable summary.
  • Project — a full JSON export of the project's documents, codes, coders, excerpts (each with who applied which code), memos, descriptors and activity log.

Nothing leaves your machine

Misket does not phone home, does not require an account, and does not upload your documents or coding anywhere as part of normal use. The only network activity related to the app itself is you downloading a release or, in future, an update check you would be asked about explicitly. Any AI-assisted features on the roadmap are planned to be opt-in and to use a key or model you supply yourself — never on by default.
