# Tool comparison and gap analysis

_Research notes for Misket, based on official documentation, help centres and
manuals for NVivo, ATLAS.ti, MAXQDA, Dedoose, QualCoder, Taguette, Quirkos
and Delve (September 2026). Sources in section 6._

## 1. Summary

The established CAQDAS tools converge on a common coding loop — select text,
apply a code from a hierarchical, colour-coded codebook, see the result as a
margin stripe, then retrieve and cross-tabulate what was coded — and differ
mainly in how much automation (auto-coding, sentiment, AI) and rigour
tooling (coder identity, Cohen's kappa, audit trails) sits on top. Misket
already covers the coding-loop core well: a real hierarchical codebook with
colours, hotkeys and drag-reorder; keyboard-first selection coding with
overlapping-excerpt lanes; merge-with-impact-preview and "move excerpts
to…"; excerpt boundary editing (grow/shrink/split/merge) that none of the
incumbents expose this directly; and, for analysis, code frequencies, a
code-by-code co-occurrence matrix, a code-by-document heatmap and descriptor
filtering, each click-through and CSV-exportable. The gaps cluster into
three groups: small coding conveniences the incumbents treat as table
stakes (in vivo coding, quick-coding the last code, a real margin
coding-stripe toggle, regex/speaker auto-coding, an uncoding/audit trail);
richer retrieval logic (Boolean/proximity AND/OR/NEAR/NOT queries, saved
analysis queries, word frequency, stemmed search); and higher-order
reporting views (framework matrices, coding-over-time by code, coder
comparison with Cohen's kappa — already an explicit roadmap item). None
require changing Misket's model — immutable text with code-point offsets,
multi-coded excerpts, descriptors and sets — they extend it.

## 4. Best-in-class implementations worth copying

1. **ATLAS.ti's In Vivo Coding** — selecting text and choosing "Code in Vivo" names a new code from the selection and applies it in one action; naming is the biggest friction point in open coding, so letting the data suggest the name keeps the coder in flow.
2. **ATLAS.ti's Quick Coding (`Ctrl+L`)** — reapplies the last-used code to a new selection; effective for runs of similar segments without touching the picker each time.
3. **NVivo's Coding Stripes** — a togglable, filterable column of coloured bars beside the text; separates "what's highlighted" from "what's coded," so stripes can be off while working and on while auditing.
4. **NVivo's node Aggregate toggle** — an explicit per-code choice of whether child coding counts as parent coding, avoiding both double-counting (always-aggregate) and an empty-looking parent (never-aggregate).
5. **MAXQDA's Autocode with paragraph/sentence expansion** — search, then auto-code each hit expanded to its sentence or paragraph with N units of context; the fastest path from "I keep finding this by hand" to a formal code.
6. **ATLAS.ti's Code Co-occurrence Table + Sankey diagram** — the same query shown as a numeric matrix (precision) and a Sankey flow (pattern-spotting), every cell/link still clicking through to the underlying quotations.
7. **NVivo's Framework Matrices with Auto Summarize** — a case-by-theme grid pre-filled with the coded text for each intersection, then hand-edited into a synthesis — the single artifact most framework analysis actually needs.
8. **MAXQDA's Intercoder Agreement / Kappa table** — a disagreement row opens the Code Matrix Browser for that document, so reliability reporting and repair live in the same view.
9. **Quirkos's bubble-size-as-frequency canvas** — frequency is a physical property of the code itself while coding, making over- or under-coded themes obvious without leaving the screen.
10. **Dedoose's normalized Code × Descriptor chart** — automatically corrects for unevenly-sized descriptor groups, avoiding the most common mixed-methods reporting mistake.
11. **Taguette's lightweight REFI-QDA (.qdc) export** — proof a small open-source tool can interoperate with the "serious" packages, lowering the cost of trying it.
12. **Misket's own excerpt-boundary editing** (grow/shrink by word or character, split, merge, keyboard- and drag-driven, all undoable) — none of the eight incumbents expose boundary refinement this directly; worth protecting as a genuine differentiator.

## 5. Recommended additions for Misket, ranked

1. **In vivo coding** — _S_ — v0.2 (alongside #10 codebook import/export) — When `Ctrl/⌘+K`'s "create on the spot" path has no typed name yet, pre-fill it with the current selection's text (trimmed/truncated), still editable before saving.
2. **Coding history / uncoding audit trail** — _M_ — ROADMAP #25 change log (v0.4) — Append-only `activity_log` (`excerpt_id | code_id | action | at`) written by the transactions that already touch `excerpt_codes`; a chronological list per excerpt/code, no coder identity required yet.
3. **Word frequency view** — _S_ — NEW, pairs with v0.2 analysis views — A new analysis tab counting tokens over a document/code-set selection (reuse the search tokenizer), sortable table first, word cloud as a stretch goal, click-through via existing find-in-project.
4. **Boolean/proximity query builder for co-occurrence** — _M_ — extends #4 (done) — Generalize `db::analysis::co_occurrence`'s "ranges overlap" test into a small expression evaluator (AND/OR/NOT, NEAR(n) on code-point distance) above today's matrix, so the matrix becomes one saved case of the general query.
5. **Auto-code by pattern/regex and by speaker turn** — _M_ — ROADMAP #16 (later) — Extend find-in-project to accept regex; add "Autocode all matches" and, once turn detection lands, "Autocode this speaker's turns," both writing ordinary `excerpts`/`excerpt_codes` rows.
6. **Text search with stemming** — _S_ — extends #1 (done) — Optional "match word forms" toggle in `FindBar.tsx`/project search using a small stemmer before substring comparison; synonyms via a user-editable thesaurus later.
7. **Quick-code (repeat last-used code)** — _S_ — NEW, small addition beside per-code hotkeys — Track the most-recently-applied code id in UI state; bind a shortcut (e.g. `Ctrl/⌘+Shift+K`) that applies it to the current selection via the same coding path as a hotkey.
8. **Coder identity + Cohen's kappa** — _L_ — ROADMAP #21 + #22 (v0.4, already planned) — Nullable `coder_id` on `excerpt_codes`, a coder filter in the browser, and a comparison view computing % agreement and kappa from two coders' overlapping ranges on shared documents.
9. **Framework matrix view** — _L_ — NEW, companion to the code-by-document heatmap — Document-by-code grid reusing `code_by_document`'s shape, but each cell shows an editable summary backed by a new `framework_summaries (document_id, code_id, text)` table, pre-filled from excerpt snapshots at that intersection.
10. **Sentiment/magnitude on excerpts** — _M_ — ROADMAP #8 (v0.2, already planned) — Optional integer `weight` (1–5) or enum `sentiment` on `excerpt_codes` (per code-application, since one excerpt may differ by code), surfaced in the picker and as a filter/summary column.
11. **Coding-over-time chart for a chosen code** — _S_ — extends #12 (done) — Reuse the overview's "excerpts over time" data, filterable to one code/set and groupable by a date descriptor, alongside the existing dashboard chart.
12. **Cluster/hierarchy visualization of the codebook** — _L_ — NEW, pairs with the co-occurrence matrix — A treemap sized by `code_frequencies`, plus similarity clustering (Jaccard over shared excerpts from the existing pair counts), as a new analysis tab.
